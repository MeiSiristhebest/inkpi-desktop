# InkPi 与 Desktop 写作产品优化方案

日期：2026-10-12。状态：实施中。CLI 写作批次的逐条进度、超时和结果保存已实现；Desktop 本地 pin 与 sidecar 已对齐到 schema 3 的 Runtime 提交。完整产品验收仍未完成。

**两项目标都未全部完成。** 草稿恢复、数据写入保护、插件启停、来源校验和浮层交互已有本地修复；全面 Pi 适配、44 个插件的生产验收、写作质量评价和同版交付仍有缺口。本方案按当前源码和可执行证据安排工作，不以注册数量、测试总数或打包成功作为产品完成判据。

## 1. 产品目标与架构边界

保留原始设计的主要流程：作者在章节正文中写作，按需参考人物、设定、大纲和素材，取得 AI 建议，审阅、采纳或拒绝，保存并能够撤销和恢复。网文需要支持分卷长篇、人物口吻、信息差、伏笔、章尾与更新节奏；这些能力应服务于正文写作。

依据：原始设计资产 `novel_writer_os_assets/00_MASTER_INDEX_AND_VISION.md`、`03_DESKTOP_GUI_AND_SAFETY_ENGINE.md`、`05_PLUGINS_AND_EXTENSIONS_CATALOG.md`；当前 [产品不变量](../specs/product-invariants.md) 与 [架构](../../ARCHITECTURE.md)。原始资产记录意图，不能替代当前实现和验收证据。

- Desktop 负责创作领域、编辑器、审阅和交互；Runtime 负责通用任务执行、模型、工具、上下文、日志与恢复。
- Desktop 创作存储继续作为作品事实的权威来源；Runtime 的索引、投影和缓存不能反向成为第二份创作权威。
- AI 结果经过 Proposal → Review → Accept，并校验作品、章节、来源修订和原文。推测、作者指定位置和可核验出处分别表示。
- 沿用 ChapterMutationService、任务中心、ToolRegistry、插件宿主、Base UI 门面和已有数据端口。跨模块改动先定义合同，不另建任务库、组件库或插件宿主。
- 单人离线写作、保存与恢复不依赖 MCP、PTY、远程沙箱或联网模型。插件是否存在、是否启用、是否出现在导航分别管理。

## 7. 44 个插件的完整治理与验收

每个插件需要核对下面七项，完成一项才更新对应状态：

2026-10-14 调整优先级：插件的核心缺口是能力有效性，不能靠组件迁移、来源标签或规则测试关闭。合成反例已复现黄金三章将否定词表打成 91 分、空稿生成缺陷诊断，读者模拟器为空稿生成赞扬与点赞，影子视角把“没有跪下”当成跪下。先实施领域算法、上下文、可核验结果与独立评测；共享组件继续服务这些流程。见 [能力可靠性审查与第一批修复](../evidence/plugin-capability-reliability-2026-10-14.md)。

黄金三章已停止生成无校准质量分，返回词项位置与真实检查范围；AI 回执必须通过结构与原文引用校验，当前输入文本变化后失效，旧评分记录保留。定向核心验证 10 个文件、80 项通过；备份与组件补验 3 个文件、30 项通过（含 5 项重叠），实际证据快照与旧分数可导出并复制导入，原记录不变。类型、改动文件 lint、生产构建和 parity 通过；完整结果见审查文档。此项仅关闭已复现的无依据结论与节选引用绑定问题，多章来源修订、开篇语义质量与量化目标仍未验收。其余插件中的规则误判、固定评论和未经校准的概率仍待逐项改造。

2026-10-14 补充：Consistency 抽屉此前把已保存的 Combat Sandbox 警告按双方名称匹配到当前正文，但事件没有章节或修订身份。抽屉现在把它单列为未绑定章节的沙盘预警，不计入正文候选，并标明出处缺失。事件携带保存的对决记录 ID，抽屉按 ID 更新同一条并保留相同角色之间的不同对决；警告仍只保存在 EventBus 内存回放与组件状态中，重启后不会恢复。标题和说明已明确标为本窗口事件。主视图也改正了例外词说明：命中作者登记的例外词仍需核对，不会自动判定越阶合理。POV 主视图保存规则后现在发出作品范围事件，已打开的抽屉据此重读持久化配置并重跑；此前它只在正文或作品变化时刷新。历史验证：合并运行 Consistency/Combat/POV/EventBus 共 14 个测试文件、65 项通过；另一次 33 文件组合复验 153 项通过。当前新增加的对决 ID 回归未运行；当前 TypeScript、Prettier 检查通过。详见 [能力可靠性审查](../evidence/plugin-capability-reliability-2026-10-14.md)。这些修改关闭事件错配、同名对决去重和旧规则结果不刷新，并纠正一条说明；不证明沙盘推演或完整语义判断准确，44 项七类生产验收仍未完成。

1. 生命周期：启用、停用、重新启用、切作品、冷加载、加载失败。停用后不拦截快捷键、不运行后台任务、不保留可呼出的失效命令。
2. 范围与数据：作品、章节、选区明确；主视图与抽屉一致；空状态、未知章号、修订与出处不造假；写入经过现有服务。
3. 交互：名称、键盘、焦点、关闭、响应布局；保留作者的表单内容和返回位置。
4. AI 结果：未配置/离线、请求、运行、取消、失败、重试、恢复、过期；显示实际来源并提供任务中心入口。
5. 采纳：建议先审阅；变更冲突可解释；接受/撤销都绑定原作品、章节、修订。
6. 持久化：保存失败、连续操作、重载、跨窗口、迁移和备份恢复；成功提示与落库一致。
7. 质量：针对预期任务有可验证的输入、领域算法与结果合同；用独立标注和代表样稿记录误报、漏报、弃答及作者评审。本地词项、模型解释和观测到的读者效果分别验收；没有经验校准，不输出质量分或商业概率。来源标签和已通过的规则测试不能单独证明能力有效。

重复概念按领域映射治理：世界书/势力/战后状态共享人物与关系引用；时间线/历法/地理共享可核验事件与时间出处；伏笔/线索/契诃夫之枪共享标识与章号语义；读者/钩子/黄金三章等共享来源和评测协议。先记录现有数据所有者及引用，再做可逆迁移；本轮不直接合并 schema 或删除插件。

## 10. 验收与文档同步

### 主流程

隔离数据中的 Web 流程：新建/导入作品 → 写章与 IME → 切章/切视图 → 续写/改写/分析 → 审阅采纳 → 撤销 → 保存 → 重载/恢复 → 备份/导入。Web 使用项目本机测试服务，不要求外部部署。

Tauri 单独验证原生菜单、sidecar 生命周期、系统凭据、WebView profile 隔离和安装/卸载。前端 parity 不等于这些壳功能已通过；旧 sidecar 连接也不能证明当前 Runtime 工作树已集成。

真实模型先验一条可用路线，再扩供应商。保存原始合成/授权输入、实际结果、版本、模型、范围、来源、用量与失败。续写、选区改写、连续性、推演、提炼五条流程分别验证；模型返回合法 JSON 与写作质量分别计分。

### 质量与性能

- 质量：人物口吻、已知/未知信息、世界观、时间顺序、伏笔、改写意图、语义保持和作者编辑负担。使用人工标注、正反例、成对盲评与作者采纳；将模型判断和规则分数分开。
- 规模：短/长章节、100/300 章合成或获授权作品、跨卷、空/稀疏领域数据。未经授权不上传真实稿件。
- 指标：输入、切章、保存、检索的 p50/p95；模型首 token、完成时间、取消响应、无效重复请求、用量/费用、缓存命中和内存。先测相同机器/模型/数据基线，再确定阈值和优化收益，不预先许诺未经测量的提速比例。
- Runtime：按实际改动运行 `pnpm run check`、`pnpm run lint`、`pnpm run test:coverage`、构建与 clean-consumer/sidecar 专项；Desktop 使用 typecheck/lint、相关测试、coverage/build/parity。源代码、模拟供应商、真实供应商、GUI 和安装包结果分开报告。
